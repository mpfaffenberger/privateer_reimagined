# Cinematic DSL — `assets/cinematics/<id>.json`

Phase 1 of the cinematic system. A cinematic is a **timeline of cues** the
in-engine director (`src/cinematic.{h,cpp}`) plays back over live Flight:
it drives the camera on splines, spawns/animates real ships, plays audio by
filepath, and layers a 2D overlay (letterbox, fades, subtitles, comm-VDU
portrait panels).

This DSL is **flight-space first**. Base-interior / concourse cutscenes
(actors on foot, room cameras) are explicitly **v2** — not covered here.

Design rules baked in (match the rest of the engine):

- **Non-fatal data.** A missing or unparseable cinematic file logs one line
  and no-ops. Same policy as `voice::load` / `comm::load` /
  `scripted::load`. A cinematic never crashes the game.
- **No AI / network / image-gen in the engine.** The game only ever *loads
  PNGs by path*. All portrait art is pre-generated by the Python tooling
  in a later phase and dropped into `assets/cinematics/portraits/...`.
- **The director owns the camera exclusively while active**, and a
  cinematic only starts from `Flight`. The death cinematic (`Dying`)
  interrupts a cinematic — never the reverse.

---

## Top-level object

```json
{
  "id": "intro_troy",
  "letterbox": true,
  "skippable": true,
  "location": { "system": "troy", "nav": "Troy Nav 8" },
  "timeline": [
    { "t": 0.0, "cmd": "fade_in", "dur": 1.0 },
    ...
  ]
}
```

| field       | type    | default | meaning                                                        |
|-------------|---------|---------|----------------------------------------------------------------|
| `id`        | string  | filename stem | Logical id. `cinematic::play("intro_troy")` loads `assets/cinematics/intro_troy.json`. |
| `letterbox` | bool    | `true`  | Draw 2.35:1 cinematic bars top & bottom (animated in/out).     |
| `skippable` | bool    | `true`  | If true, the skip key (`Esc`) ends the cinematic early.        |
| `location`  | object  | absent  | **Entry-point** (optional): `{ "system", "nav" }` — the backdrop the scene was authored against. Before playback the host teleports the player to that nav (the `/dock` parking recipe); if the player is in a *different* system it queues the deferred system switch first and plays on arrival. An unknown `system` **refuses the play** with a clear error; an unknown `nav` name plays in place with a log line. Without a `location`, play happens wherever the player is (legacy). |
| `timeline`  | array   | `[]`    | Cues, each with a start time `t`. Order-independent; the director sorts by `t`. |

---

## Cue anatomy

Every cue has:

| field | type   | meaning                                                        |
|-------|--------|----------------------------------------------------------------|
| `t`   | number | Start time in **seconds** from cinematic start.                |
| `cmd` | string | One of the commands below.                                     |

Plus command-specific fields. The cinematic ends when the last cue's
effect finishes (or on skip, or when a `end` cue fires).

Coordinates are **world metres** (same space as `system.json` nav points
and ship positions), `[x, y, z]`.

---

## Command list (Phase 1)

### `fade_in` / `fade_out` — `{ dur }`
Fade the screen from/to black over `dur` seconds. `fade_in` clears an
existing black screen; `fade_out` drives it to black (and holds until the
cinematic ends). Default `dur` = 1.0.

### `music` — `{ file }`
Play a music bed **looped, 2D** via `audio::play_file`. `file` is a path
under `assets/cinematics/audio/` (e.g. `"audio/intro_theme.mp3"`). Missing
file → silent. Replaces any music bed the cinematic previously started.

### `sfx` — `{ file, pos? }`
One-shot sound. If `pos: [x,y,z]` is present it plays **positional**
(`audio::play_file_world`) against the cinematic camera; otherwise **2D**.
`file` under `assets/cinematics/audio/`.

### `camera_path` — `{ keys, ease?, dur }`
Fly the cinematic camera through a spline of keyframes over `dur` seconds.

**CAMERA RULE (mandatory):** during any `line` cue, the camera MUST be in a
close-up on the speaker's ship — `look_at: "ship:<speaker_actor>"` with the
camera positioned 200–600 m from the tracked ship. This is the default
framing for dialogue. Wide establishing shots are only for moments with no
active dialogue (approach, arrival, post-battle). The agent authoring a
cinematic must emit a `camera_path` cue that starts at or before each `line`
cue, tracks the speaker's actor, and holds a close-up for the line's full
duration. No two `camera_path` cues may overlap in time.

**FOLLOW MODE:** set `"follow": "<actor>"` on a `camera_path` cue to make the
camera track a ship at a fixed offset (the first key's `pos` is the OFFSET
from the ship, not a world position). The camera matches the ship's velocity
and heading every frame — far more natural than spline interpolation for
tracking moving ships. For capital ships (drayman), use ~1500 m offset; for
fighters, ~300 m. To frame an entire wing/formation, pass a comma-separated
list: `"follow": "talon1,talon2,talon3,talon4,talon5"` — the camera targets
the centroid of all listed ships.

```json
{ "t": 0.0, "cmd": "camera_path", "dur": 6.0, "ease": "smooth",
  "keys": [
    { "pos": [0, 200, 3000],  "look_at": [0, 0, 0] },
    { "pos": [1500, 0, 1500], "look_at": "ship:grayson" }
  ] }
```

- `keys[].pos`     — camera world position at that key.
- `keys[].look_at` — either a `[x,y,z]` world point **or** the string
  `"ship:<actor>"` to track a spawned actor's live position.
- `ease` — `"smooth"` (Catmull-Rom through the key positions, the default)
  or `"linear"` (piecewise straight segments). `look_at` interpolates
  linearly between keys regardless.
- Position is a **Catmull-Rom** spline for `smooth`; endpoints are
  duplicated so the path starts/ends exactly on the first/last key.

### `spawn` — `{ actor, class, faction?, pos }`
Bring a real ship into the world through the shared `encounters::SpawnFn`
recipe (same seam the encounter director + `/spawn` use — DRY). `actor` is
a **logical name** other cues reference (`actor_path`, `look_at:
"ship:<actor>"`). `class` is a `ship_class` key (`"talon"`, `"centurion"`,
…). `faction` (optional, default `civilian`) is a `faction::from_name` key.

```json
{ "t": 0.0, "cmd": "spawn", "actor": "grayson", "class": "centurion",
  "faction": "confed", "pos": [500, 0, 800] }
```

Spawn failures (class/atlas not loaded) log and no-op — the actor simply
never appears and any `look_at`/`actor_path` referencing it is skipped.

### `actor_path` — `{ actor, keys, dur }`
Animate a spawned actor along a Catmull-Rom position spline over `dur`
seconds. `keys[].pos` only (actors face their direction of travel).

```json
{ "t": 1.0, "cmd": "actor_path", "actor": "grayson", "dur": 5.0,
  "keys": [ { "pos": [500,0,800] }, { "pos": [0,0,0] } ] }
```

### `line` — `{ speaker, portrait, text, voice_file?, side, dur }`  ← the composite beat
A single spoken line: a comm-VDU **portrait panel** slides in on `side`
(`"left"` or `"right"`), a **subtitle** shows `text`, and — if
`voice_file` is present — the clip plays 2D. Two `line` cues overlapping in
time on opposite sides render **both** panels simultaneously (an exchange).

```json
{ "t": 2.0, "cmd": "line", "speaker": "Grayson",
  "portrait": "portraits/grayson/intro_003.png",
  "text": "I didn't sign up for this.",
  "voice_file": "audio/grayson_intro_003.mp3",
  "side": "left", "dur": 3.5 }
```

- `speaker`    — nameplate text.
- `portrait`   — PNG path under `assets/cinematics/` (see dimensions
  below). Missing PNG → panel shows the nameplate + subtitle with a
  neutral frame, **never crashes**.
- `voice_file` — optional clip under `assets/cinematics/audio/`.
- `side`       — `"left"` (default) or `"right"`.
- `dur`        — seconds the panel + subtitle stay up (then slides out).

### `subtitle` — `{ text, dur }`
A bare centered subtitle with no portrait — narration / scene-setting.

### `end` — `{ actions? }`
Explicitly end the cinematic now. `actions` is a list of plot-grammar
tokens run through `plot::run_actions` (the SAME grammar as fixers /
scripted-encounter `on_cleared`): `"set_flag:x"`, `"clear_flag:x"`,
`"give_item:x"`, `"remove_item:x"`, or any campaign token. This is how a
cutscene advances the campaign when it finishes.

```json
{ "t": 12.0, "cmd": "end", "actions": ["set_flag:intro_seen"] }
```

If no `end` cue exists, the cinematic ends when the last cue's `dur`
elapses.

## Portrait panel — **PINNED dimensions** (Phase 3 depends on these)

The Phase 3 portrait-generation pipeline generates PNGs to *exactly* these
dimensions, so they're fixed here BEFORE any art is made:

| thing                     | value                                   |
|---------------------------|-----------------------------------------|
| **Source PNG size**       | **512 × 640** px (portrait, 4:5)         |
| Format                    | 24/32-bit PNG, RGBA (alpha ignored today)|
| Directory                 | `assets/cinematics/portraits/<char>/`    |
| On-screen panel height    | **34%** of framebuffer height            |
| On-screen panel width     | height × (512/640) = height × 0.8        |
| Left panel anchor         | bottom-left, inset 4% of screen w/h      |
| Right panel anchor        | bottom-right, inset 4% of screen w/h     |
| Frame                     | 3 px comm-VDU border, cyan (`#33ccff`)   |
| Nameplate                 | bar across the panel bottom, speaker text|
| Slide-in / slide-out      | 0.35 s ease, from the panel's own edge   |

**Rationale for 512×640:** portrait (taller than wide) frames a
head-and-shoulders comm shot; 4:5 is a clean ratio that scales to the ~34%
screen-height panel without letterboxing the art itself, and 512px wide is
plenty for a 2D VDU inset at 1080p/1440p without being wasteful for the
per-line generation volume Phase 3 implies.

## Notes for Phase 2 / Phase 3

- **Phase 2 (hot reload + agentic control):** the director exposes
  `cinematic::load / play / stop / active / skip`. Phase 2 wires
  `POST /cinematic/play|stop|reload|seek` + `GET /cinematic/status` to
  these and emits `"cinematic"` events (cue fired, line shown w/ portrait
  path, ended/skipped) into the `/events` ring so the agent can assert
  timing without screenshots. `reload` = re-`load()` the file mid-play.
- **Phase 3 (portrait gen):** every `line.portrait` is a path to a
  pre-generated 512×640 PNG. The engine NEVER generates art. The character
  bible + reference-conditioned generation live entirely in Python tooling.
- **v2 (base interiors):** concourse/bar cutscenes need a room-camera +
  on-foot actor model this DSL does not have. Deferred.

## Triggering a cinematic from the campaign (Phase 5.2, #143)

Cinematics play from **pure data** via the plot action grammar
(`plot::run_action`), the same one-token grammar as `set_flag:x`,
`pay:5000`, `give_item:x`. The token is:

```
play_cinematic:<id>          # <id> = assets/cinematics/<id>.json (no path, no .json)
```

Drop it into ANY action list that already runs through the grammar — a
fixer's `done_actions` / `accept_actions` (bar conversations, in
`fixers.json`) or a scripted encounter's `on_cleared` / `on_dialogue_done`
(`scripted_encounters.json`). No C++ change is needed per cinematic.

**2-line author examples:**

```jsonc
// fixers.json — a bar conversation that ends by launching you into a cutscene:
"done_actions": ["set_flag:sandoval_done", "play_cinematic:confrontation_demo"]

// scripted_encounters.json — clear the ambush, then roll the aftermath scene:
"on_cleared": ["set_flag:riordian_dead", "play_cinematic:demo_exchange"]
```

**Flight vs Landed (the deferral rule).** A cinematic only ever *starts*
from Flight (Phase 1 rule — it overlays the live sim). The token respects
that automatically:

- **In Flight** (e.g. an encounter `on_cleared`): plays immediately.
- **Landed** (e.g. a bar fixer `done_actions`): the id is **deferred** and
  plays the instant the player next launches to Flight — so a bar beat can
  legitimately end "...and then you launch into an ambush cutscene." The
  deferral is session-only (not serialized): a save+reload while Landed
  drops the pending trigger, but the fixer *flag* that gated it persists,
  so authors should treat the cinematic as flavour, not durable state.
- **Unknown id / parse error:** logs one line, no crash (same
  "log + carry on" policy as every other token and as the director itself).

**Where it's wired:** `campaign.cpp`'s action handler owns the
`play_cinematic:` token (next to `pay:`, `m21:take_gun`, …). Because
starting a cinematic needs the live `GameMode`, which lives in `main.cpp`,
the handler routes the id through a `campaign::set_cinematic_trigger`
callback that `main.cpp` wires once at startup (Flight → play now, Landed →
defer). The token grammar itself stays in `plot.cpp`; no world-touching
code leaks into plot core.

**Proving it fires (no data-file edits needed):** the built-in dev lever
runs any grammar token on the main thread —

```bash
curl -s -X POST localhost:47001/plot -d '{"action":"run","id":"play_cinematic:demo_exchange"}'
curl -s localhost:47001/events        # -> cinematic: "started id=demo_exchange dur=10.00", cue ...
curl -s localhost:47001/cinematic/status
```

## Director robustness / error behaviors (Phase 6.2)

The director follows the engine-wide "log one line + degrade, never crash"
contract. Concretely:

* **Malformed / partial cinematic file** — a missing *optional* field
  (`voice_file`, `faction`, `pos`, `look_at`, `ease`, `side`, `actions`, …)
  is simply the default; a bad *type* falls back to the default; an unknown
  `cmd` or a non-object timeline entry is skipped. A structural failure (root
  not a JSON object, unreadable file) makes the cinematic a **no-op** and sets
  `last_error`. Parsing **never throws** into the game loop. Covered by
  `tools/test_cinematic.cpp` (`cmake --build build --target test_cinematic`).
* **Missing PNG / audio** — the portrait draws a neutral frame; missing
  music/sfx/voice no-ops. Never a crash.
* **`POST /cinematic/play` while one is already playing** — **rejected** (not
  replaced). Reply: `{"ok":false,"error":"a cinematic is already playing
  ('<id>') - stop it first"}`. Call `/cinematic/stop` first.
* **`POST /cinematic/play` while not in Flight** (Landed / title / dying) —
  **rejected**. Reply: `{"ok":false,"error":"not in Flight (a cinematic only
  starts from Flight)"}`. (The `play_cinematic:` campaign token instead
  *defers* until the next undock.)
* **`/cinematic/seek` t out of range** — clamped to `[0, duration]`.
* **Skip (Esc) mid-fade/mid-line, or player death mid-cinematic** — both route
  through the single `stop()`/`end_cinematic()` teardown: music killed, overlay
  cleared, camera + pilot input released the same frame.
* **Empty / end-only timeline** — loads and completes cleanly (no-op).

## Dynamic actor class: `$player`

A `spawn` cue with `"class": "$player"` substitutes the player's CURRENT
ship class at play time (`PlayerState::ship_class_name`), so the hero actor
always matches what the player is really flying. Use it for any actor that
represents the player. Authored-time classes remain literal for everyone else.

## Outcome `player_pos`

`"outcome": {"player_pos": [x, y, z], ...}` drops the player at an exact
world position when the cinematic ends (natural or skipped). Takes precedence
over `player_at_nav` — use it when a finale deliberately ends away from any
nav (e.g. an ambush 100k up the approach corridor).
